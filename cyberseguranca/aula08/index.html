Conceito

O que é um Firewall?

O que ele faz

Controla o tráfego entre redes de confiança diferentes, aplicando regras objetivas de IP, porta e protocolo.

Onde ele fica

Classicamente na borda da rede, mas também pode segmentar internamente (entre subnets, entre serviços).

O que ele decide

Se a conexão PODE acontecer — não o que vai ser dito dentro dela.

O que ele não é

Não é a única linha de defesa — é a primeira de várias, como veremos na defesa em profundidade.

Fundamentos

Quatro Gerações de Firewall

L3/L4

Filtro de Pacotes

Analisa cada pacote isolado: IP de origem/destino, porta, protocolo. Rápido, mas sem memória da conexão.

L4

Stateful

Rastreia o estado da conexão (handshake, sessão) numa tabela. Padrão desde os anos 1990.

L4-L7

Proxy / App Gateway

Intermediário que termina a conexão e abre outra — enxerga o protocolo da aplicação.

L3-L7

NGFW

Soma tudo isso + reconhecimento de aplicação + usuário + IPS integrado e inteligência de ameaças.

iptables — regras sem estado
# só cabeçalho: origem, porta e protocolo
iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 22 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
iptables -P INPUT DROP
Cada linha é avaliada de cima para baixo; o primeiro casamento decide. O que ninguém liberou cai na política DROP.
  • O que olha: IP de origem e destino, porta e protocolo — só o cabeçalho do pacote.
  • Limite: não tem memória. A resposta de uma conexão legítima (porta alta) também precisaria de uma regra própria.
  • Onde ainda aparece: ACLs de roteadores e switches e as Network ACLs (NACL) da AWS, que são sem estado.

iptables — com rastreamento de conexão
# conntrack: a resposta entra pelo estado
iptables -A INPUT -m conntrack \
  --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -p tcp --dport 443 \
  -m conntrack --ctstate NEW -j ACCEPT
iptables -P INPUT DROP
A primeira regra é a que “lembra”: aceita o que pertence a uma conexão já registrada na tabela de estados.
  • O que olha: o cabeçalho e o estado da conexão numa tabela (origem, destino, fase do handshake).
  • Ganho: a resposta de uma conexão iniciada por dentro entra sem regra extra; um pacote avulso, sem entrada na tabela, é descartado.
  • Hoje: é o comportamento padrão dos Security Groups da AWS. Ainda assim, só olha estado — não o conteúdo.

A Camada que Faltava

WAF: a Camada que o Firewall de Rede Não Vê

Firewall de Rede / NGFW

Vê o envelope

  • Opera em L3/L4 (+ reconhecimento de app no NGFW)
  • Decide por IP, porta e protocolo
  • Libera :443 por ser HTTPS válido
  • Sem decifrar o TLS, não lê o corpo da requisição
Proxy Convencional

Filtra a saída do cliente

  • Intermediário de requisições de SAÍDA
  • Filtra URLs, categorias, faz cache
  • Protege a rede do usuário, não a aplicação
  • Direção oposta à do ataque de hoje
WAF

Lê a carta dentro do envelope

  • Opera em L7, como reverse proxy da aplicação
  • Interpreta HTTP, JSON, GraphQL
  • Compara o payload a regras (ex.: OWASP CRS)
  • Pega SQL Injection, XSS, Command Injection
Mesma porta 443, três níveis de visibilidade diferentes — por isso a injeção do problema inicial passou.

Uma Regra de Firewall, de Verdade

ufw — host / servidor
# só a subnet de apps acessa o Postgres
sudo ufw allow from 10.0.2.0/24 \
  to any port 5432 proto tcp
sudo ufw default deny incoming
security-group.tf — Terraform / AWS
resource "aws_security_group_rule" "db_from_app" {
  type           = "ingress"
  from_port      = 5432
  to_port        = 5432
  protocol       = "tcp"
  security_group_id = aws_security_group.db.id
  source_security_group_id =
    aws_security_group.app.id
}
regra = quem (origem) + o quê (porta/protocolo) + para onde (destino). Nada sobre o conteúdo do pacote.

Conceito

O que São IDS e IPS?

IDS — Detection

Passivo

  • Detecta e alerta
  • Não intervém no tráfego
  • Posicionado em modo de escuta (cópia do tráfego)
IPS — Prevention

Ativo

  • Detecta e bloqueia em tempo real
  • Posicionado inline, no caminho do tráfego
  • Pode derrubar uma conexão automaticamente
NIST SP 800-94 usa o termo combinado IDPS — na prática, o mesmo motor normalmente faz as duas coisas; o que muda é o modo de operação.

Desafio Operacional

Falso Positivo x Falso Negativo

Falso Positivo

Legítimo marcado como ataque

  • Em modo IPS (bloqueio ativo), derruba tráfego real
  • Pode quebrar uma venda, uma integração, um relatório
Falso Negativo

Ataque real não detectado

  • A violação acontece sem nenhum alarme
  • É o risco que a detecção deveria mitigar
Por isso muitas empresas rodam o motor em modo IDS por semanas, ajustando assinaturas, antes de confiar em IPS bloqueando em produção.

O Desafio do Tráfego Criptografado

A maior parte do tráfego hoje é HTTPS/TLS. Um IDS/IPS que só olha pacotes criptografados vê bytes — não conteúdo.

Terminação TLS na Borda

Load Balancer, WAF ou proxy reverso decriptografam no ponto de entrada — prática comum, ponto natural de inspeção.

Interceptação TLS de Saída

Forward proxy com CA interna inspeciona tráfego de estações — mais invasivo, quebra certificate pinning em apps.

Desafio Operacional

Egress Filtering: a Porta que Ninguém Tranca

A maioria das regras de firewall foca em quem pode ENTRAR. Tráfego de SAÍDA costuma ser "permitir tudo" por padrão.

!

O Risco

Após ganhar execução de código, o atacante abre uma conexão de SAÍDA (reverse shell) ou exfiltra dados — e isso raramente é bloqueado.

✓

A Mitigação

Egress Filtering: restringir ativamente quais domínios/IPs/portas de SAÍDA cada serviço pode acessar.

Um firewall que só filtra entrada é uma porta com tranca só por fora.
