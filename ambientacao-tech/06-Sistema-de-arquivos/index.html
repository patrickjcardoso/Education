05 · Gancho do mundo real

50 GB livres, e o vídeo de 6 GB não copia

Uma colega precisa levar a gravação de uma palestra para a TV da sala de reuniões. Ela arrasta o vídeo para um pendrive novo de 64 GB, quase vazio, e recebe um erro.

Tentativa

Arrastar palestra.mp4 (6 GB) para o pendrive com 50 GB livres.

Erro

Diagnóstico

O pendrive veio formatado em FAT32, que não aceita arquivos com 4 GiB ou mais, não importa o espaço livre.

06 · Mini-aula · 15 min

O mínimo para começar: 3 ideias

1

O que é um sistema de arquivos

O componente do SO que organiza, nomeia, indexa e recupera dados num dispositivo de armazenamento. Ele divide o disco em blocos (no Windows, clusters) e registra quais blocos pertencem a qual arquivo.

2

Hierarquia e metadados

Arquivos ficam numa árvore de diretórios. Cada arquivo carrega metadados: nome, tamanho, datas, permissões, dono e a localização dos seus blocos.

3

Implementações diferentes

FAT32, NTFS, ext4 e APFS resolvem o mesmo problema com estruturas distintas: tabela de alocação, MFT, inodes e B-trees. Cada escolha tem impacto em desempenho, limites e confiabilidade.

programa ──(write)──▶ kernel ──▶ sistema de arquivos ──▶ driver ──▶ disco (setores/blocos) "quais blocos estão livres?" "onde estão os blocos de notas.txt?"

Para aprofundar: DEITEL, Sistemas Operacionais, e TANENBAUM, Sistemas Operacionais Modernos, capítulos sobre sistemas de arquivos (seção 25).

07 · Metadados

O arquivo tem dados. O sistema de arquivos guarda os dados sobre os dados.

Dados × metadados

Dados: o conteúdo (o texto, os pixels da foto).

Metadados: tudo o que o SO sabe sobre o arquivo:

  • tamanho lógico e blocos alocados
  • identificador único: inode (Linux/macOS) ou File ID (NTFS)
  • dono, grupo e permissões (ou ACL)
  • datas (timestamps)
  • onde estão os blocos no disco

No Linux, o nome não fica no inode: fica no diretório, que é uma lista "nome → inode".

Os timestamps, sem confusão

Linux / macOSSignificaWindows
atime (Access)último acesso (leitura)LastAccessTime
mtime (Modify)última alteração do conteúdoLastWriteTime
ctime (Change)última alteração dos metadados (permissão, dono, nome)(sem equivalente direto)
Birth (crtime)criaçãoCreationTime
Pegadinha clássica: no Linux, ctime não é a data de criação. Um chmod muda o ctime. A data de criação aparece como Birth no stat (ext4 e kernels recentes). E o atime nem sempre muda a cada leitura: a opção relatime, padrão no Linux, reduz essas gravações para poupar o disco.

Como ler a saída do stat (Linux)

$ stat relatorio.txt
  File: relatorio.txt
  Size: 10000      Blocks: 24      IO Block: 4096  regular file
Device: 259,2   Inode: 1835263   Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/ aluno)  Gid: ( 1000/ aluno)
Access: 2026-10-20 19:05:12 -0300
Modify: 2026-10-18 21:40:03 -0300
Change: 2026-10-18 21:40:03 -0300
 Birth: 2026-10-18 21:40:03 -0300
Size: 10000 é o tamanho lógico: o conteúdo tem 10.000 bytes.
Blocks: 24 conta unidades de 512 bytes, não blocos do sistema de arquivos: 24 × 512 = 12.288 bytes alocados = 3 blocos de 4.096.
Inode é o "RG" do arquivo. 0644 é a permissão em octal (seção 11).
Change ≠ criação. A criação é o Birth. Se aparecer Birth: -, o sistema não registrou a criação.
Repare: 12.288 − 10.000 = 2.288 bytes alocados e não usados. Isso tem nome, fragmentação interna, e é o assunto do Bloco 3. Guarde esse número.

13 · Bloco 1 · Discussão técnica coletiva

Comparando os resultados da turma

Discuta primeiro com os dados que você coletou. Os pontos-chave ficam escondidos para revisão depois da aula.

Provavelmente apareceram NTFS (Windows), ext4 (Linux) e APFS (macOS). O NTFS registra cada arquivo numa tabela central, a MFT; o ext4 usa inodes e extents; o APFS usa B-trees e copy-on-write. Mesma função, estruturas diferentes. Pendrives costumam vir em FAT32 ou exFAT.
O disco só aloca blocos inteiros. O último bloco quase sempre fica parcialmente vazio, então o alocado é maior que o lógico: é a fragmentação interna. Às vezes o alocado é menor: arquivos compactados, arquivos esparsos, ou arquivos muito pequenos guardados dentro da própria MFT no NTFS (tamanho em disco = 0).
644 deixa qualquer usuário ler: ruim para notas, senhas ou chaves (use 600). 777 deixa qualquer um alterar e executar. A regra é o princípio do menor privilégio: cada um recebe só a permissão de que precisa.
Antes de alterar a estrutura, o sistema anota a operação num diário (journal). Ao religar, ele refaz ou descarta as operações incompletas e a estrutura volta a ficar consistente, sem precisar varrer o disco inteiro. Mas, por padrão, o journal protege os metadados: o conteúdo pode voltar à versão anterior. Journaling não substitui backup.
14 · Bloco 2 · Análise comparativa

Quatro sistemas de arquivos, um mesmo problema

Cada aluno recebe um destes para pesquisar. Use estes resumos só como ponto de partida.

1977 · 1996 (versão 32)
FAT32

Uma tabela de alocação (FAT) encadeia os clusters de cada arquivo.

  • Limite de 4 GiB por arquivo
  • Sem journaling e sem permissões
  • Compatibilidade quase universal
Windows · desde 1993
NTFS

Cada arquivo é um registro na Master File Table (MFT).

  • Permissões por ACL e criptografia (EFS)
  • Journaling de metadados
  • Arquivos e volumes muito grandes
Linux · desde 2008
ext4

Inodes apontam para extents: faixas de blocos contíguos.

  • Journaling (modo padrão ordered)
  • Permissões Unix (dono, grupo, outros)
  • Padrão em distribuições e servidores
Apple · desde 2017
APFS

B-trees e copy-on-write: nunca sobrescreve no lugar.

  • Clones e snapshots instantâneos
  • Criptografia nativa
  • Otimizado para SSD, padrão no macOS e iOS
Copy-on-write (APFS): em vez de sobrescrever um bloco, grava a versão nova em outro lugar e só então troca o ponteiro. Se a energia cair no meio, a versão antiga continua íntegra. É outra forma de obter a confiabilidade que o journaling oferece.

Bloco 3 · Quanto espaço se perde em cada arquivo?

Resolva por escrito, sozinho, antes de qualquer discussão. Um sistema de arquivos usa blocos de 4.096 bytes. Um arquivo sempre ocupa um número inteiro de blocos.

  1. Um arquivo de 10.000 bytes é salvo. Quantos blocos serão alocados?
  2. Quantos bytes serão desperdiçados por fragmentação interna? Mostre o cálculo.
  3. Repita para 4.096 bytes e para 4.097 bytes. O que o contraste revela sobre o tamanho do bloco quando há muitos arquivos pequenos?
10.000 ÷ 4.096 = 2,44 → arredonda para cima: 3 blocos = 12.288 bytes. Desperdício: 12.288 − 10.000 = 2.288 bytes (o mesmo número do stat da seção 10).
4.096 B → 1 bloco, desperdício 0. 4.097 B → 2 blocos, desperdício 4.095 B (quase um bloco inteiro por causa de 1 byte!). Com milhares de arquivos pequenos, blocos grandes desperdiçam muito espaço; blocos pequenos desperdiçam menos, mas exigem mais metadados para controlar.

Contígua, encadeada ou indexada?

Em sala, simulamos com cartões numerados na mesa. Aqui, o mesmo disco de 32 blocos. Grave o arquivo A (5 blocos) com cada estratégia, depois tente ler o último bloco e crescer +2 blocos.

livreoutros arquivosarquivo Abloco índicecrescimento
No mundo real: o FAT32 é uma alocação encadeada (a tabela guarda o "próximo bloco"); o ext4 e o NTFS são indexados e agrupam blocos vizinhos em extents (ou runs), unindo o melhor dos dois mundos.
21 · Bloco 3 · Debate técnico coletivo

Fechando o Bloco 3

A indexada (ou por extents). A contígua sofre com fragmentação externa: arquivos criados e apagados o tempo todo deixam buracos que não comportam arquivos novos. A encadeada aproveita os buracos, mas o acesso a uma posição qualquer é lento. Combine com blocos pequenos para reduzir a fragmentação interna.
O HD tem cabeça de leitura e disco girando: blocos espalhados custam movimentos mecânicos (busca e rotação). O SSD é eletrônico: acessar qualquer endereço leva praticamente o mesmo tempo. Por isso não se desfragmenta SSD (só gastaria ciclos de escrita); o SO usa o comando TRIM para avisar ao SSD quais blocos ficaram livres.
É um trade-off. Blocos grandes: menos metadados e leitura mais rápida de arquivos grandes, mas muito desperdício com arquivos pequenos. Blocos pequenos: pouco desperdício, mas mais blocos para controlar. Por isso 4 KiB é o padrão de NTFS e ext4, e cartões de câmera, cheios de fotos e vídeos grandes, usam clusters maiores.

27 · Glossário da aula

Termos que você precisa dominar

Sistema de arquivos
Parte do SO que organiza, nomeia, indexa e recupera dados no armazenamento.
Bloco / cluster
Menor unidade que o sistema de arquivos aloca. Padrão comum: 4 KiB.
Metadados
Dados sobre o arquivo: tamanho, datas, dono, permissões e localização dos blocos.
Inode
Estrutura do Linux/macOS com os metadados de um arquivo, identificada por um número.
MFT
Master File Table: tabela do NTFS com um registro por arquivo.
FAT
File Allocation Table: tabela que encadeia os clusters de cada arquivo.
Extent
Faixa de blocos contíguos descrita por "início + quantidade" (ext4).
Journaling
Registro das operações antes de executá-las, para recuperar a consistência após falhas.
Copy-on-write
Grava a versão nova em outro lugar e só depois troca o ponteiro (APFS).
Fragmentação interna
Espaço desperdiçado dentro do último bloco de um arquivo.
Fragmentação externa
Espaço livre picado em buracos pequenos demais para uso contíguo.
atime / mtime / ctime
Último acesso, última mudança do conteúdo e última mudança dos metadados.
Birth (crtime)
Data de criação do arquivo no Linux/macOS.
Permissão octal
rwx de dono, grupo e outros em 3 dígitos (r=4, w=2, x=1). Ex.: 644.
ACL
Lista de controle de acesso: permissões por usuário ou grupo (NTFS, APFS).
TRIM
Comando com que o SO avisa ao SSD quais blocos ficaram livres.
