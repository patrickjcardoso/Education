06 · Mini-aula · 15 min

O mínimo para começar: 3 ideias

1

Virtualização e VM

Virtualização é uma camada de software que permite que vários sistemas operacionais compartilhem o mesmo hardware, cada um isolado como se tivesse a máquina só para si. Cada ambiente isolado é uma máquina virtual (VM).

2

Hypervisor

O software que cria, executa e gerencia as VMs, repartindo CPU, memória, disco e rede entre elas. O sistema da máquina real é o host (hospedeiro); o sistema dentro da VM é o guest (convidado).

3

Hardware virtual

A VM recebe vCPUs, memória, um disco virtual (um arquivo no host) e uma placa de rede virtual. O SO convidado acha que é hardware de verdade e se instala normalmente.

Conexão com a Aula 05: o hypervisor é quem decide quem usa o hardware, um papel parecido com o do kernel, só que um nível abaixo, entre sistemas operacionais inteiros.

10 · Bloco 1 · Pré-requisito

A virtualização começa no processador

Processadores modernos têm instruções próprias para virtualização: Intel VT-x e AMD-V (chamado SVM no BIOS). Sem elas ativas, o VirtualBox fica lento ou nem liga a VM. Elas são ligadas no UEFI/BIOS, aquele SETUP que você viu na Aula 03.

Sistema hostComo conferirResultado esperado
WindowsGerenciador de Tarefas → Desempenho → CPUVirtualização: Habilitado
Linuxlscpu | grep -i virtualizVT-x ou AMD-V
macOSsysctl kern.hv_supportkern.hv_support: 1
Aparece "Desabilitado"? Reinicie, entre no SETUP (Del, F2 ou F10, conforme o fabricante) e ative Intel Virtualization Technology ou SVM Mode. Salve e saia.
Tartaruga verde no VirtualBox (Windows)? Hyper-V, WSL2 ou a Integridade de memória estão ativos, e o VirtualBox roda por cima do Hyper-V, mais lento. Funciona; só não espere velocidade.
11 · Bloco 1 · Hardware virtual

vCPU, memória e disco virtual

⚙

vCPU

Núcleos virtuais que o hypervisor escalona sobre os núcleos (threads) reais. Dá para somar mais vCPUs entre as VMs do que núcleos existem (overcommit), mas, se todas trabalharem ao mesmo tempo, todas ficam lentas.

Regra prática: até metade das threads do host para uma VM.

▦

Memória (vRAM)

RAM do host reservada para a VM enquanto ela está ligada. O host continua precisando da dele: se faltar, os dois começam a usar o disco como memória (swap) e tudo trava.

Regra prática: deixe ao menos 4 GB livres para um host Windows ou macOS.

⛁

Disco virtual

Um arquivo no host que a VM enxerga como disco: VDI (VirtualBox), VMDK (VMware), VHDX (Hyper-V), QCOW2 (KVM).

  • Dinâmico: começa pequeno e cresce até o limite. Economiza espaço.
  • Fixo: reserva tudo na criação. Um pouco mais rápido, ocupa tudo já.
Ligando com a Aula 06: o disco dinâmico é o caso extremo de "tamanho lógico × alocado": a VM vê 25 GB, mas o arquivo .vdi ocupa só o que foi gravado. E como ele passa de 4 GiB, não cabe num pendrive FAT32.

15 · Bloco 2 · Planejamento

Antes de instalar: requisitos, ISO confiável e partições

1 · Requisitos

Consulte os mínimos do sistema que vai instalar e dê margem.

Ubuntu Desktop 26.046 GB RAM · 25 GB
Ubuntu Desktop 24.044 GB RAM · 25 GB
Ubuntu Server 26.04a partir de 1,5 GB RAM
Windows 114 GB RAM · 64 GB · TPM 2.0

2 · ISO íntegra

A ISO é a imagem do disco de instalação. Baixe só do site oficial e compare o hash SHA-256 com o publicado no arquivo SHA256SUMS. Se um único bit mudou, o hash muda inteiro.

# Windows (PowerShell) Get-FileHash .\ubuntu.iso -Algorithm SHA256 # Linux sha256sum ubuntu.iso # macOS shasum -a 256 ubuntu.iso

3 · Partições

  • MBR: padrão antigo. Discos de até 2 TiB e 4 partições primárias.
  • GPT: padrão atual, usado com UEFI. Discos enormes e até 128 partições.
  • No Linux, cada partição é montada num ponto da árvore: /, /boot/efi, e a swap (que hoje costuma ser um arquivo).

Numa VM nova, "usar o disco inteiro" é seguro: o disco é virtual.

21 · Bloco 3 · Gerenciamento

O ciclo de vida de uma VM

📸

Snapshot

Fotografa o estado da VM: disco e configuração (e a memória, se estiver ligada). A partir dali, as mudanças vão para um disco de diferenças. Restaurar descarta essas mudanças.

⧉

Clone

Completo: cópia independente de todos os arquivos. Vinculado (linked): reaproveita o disco original e grava só as diferenças. Economiza espaço, mas depende do original.

📦

Exportação (OVA)

Empacota VM e discos num único arquivo .ova, que pode ser importado em outro computador. Guardado em outro disco, serve de backup.

⇄

Migração

Mover a VM para outro host. Em data centers, a migração ao vivo (ex.: vMotion) faz isso com a VM ligada, para manutenção sem parar o serviço.

⏻

Estados

Desligar (como tirar da tomada), desligamento ACPI (pede ao SO para desligar, o certo) e salvar estado (hiberna a VM).

🗑

Exclusão

Remove a VM do VirtualBox e, se você escolher, também apaga os arquivos de disco. Não tem lixeira.

Snapshot não é backup. Ele fica no mesmo disco do host que a VM e depende do disco original. Se o SSD do notebook morrer, a VM e todos os snapshots morrem juntos. Backup é uma cópia independente, em outro lugar: um .ova num HD externo, por exemplo.

Snapshot, "quebre e restaure", clone e exportação

Roteiro (pela interface)

  1. Desligue a VM. Em Snapshots, tire pos-instalacao.
  2. Ligue, crie um arquivo teste.txt na pasta pessoal e desligue.
  3. Restaure o snapshot e ligue de novo. O arquivo ainda existe? Por quê?
  4. Crie um clone vinculado a partir do snapshot. Compare o tamanho da pasta dele com a da original.
  5. Opcional, em casa: Arquivo → Exportar para .ova num HD externo.
Os mesmos passos pelo terminal do host
VBoxManage snapshot ubuntu-lab take pos-instalacao --description "SO limpo"
VBoxManage snapshot ubuntu-lab list

VBoxManage controlvm ubuntu-lab acpipowerbutton      # desliga "pelo botão"
VBoxManage snapshot ubuntu-lab restore pos-instalacao  # com a VM desligada

# clone vinculado (só as diferenças) e clone completo
VBoxManage clonevm ubuntu-lab --snapshot pos-instalacao --options link --name ubuntu-linked --register
VBoxManage clonevm ubuntu-lab --name ubuntu-full --register

VBoxManage export ubuntu-lab -o ubuntu-lab.ova        # backup portátil
Resposta esperada no passo 3: o arquivo some. Ele foi gravado no disco de diferenças criado depois do snapshot, e restaurar descarta esse disco. É assim que o laboratório "volta ao zero" a cada aula.
24 · Bloco 3 · Situações-problema · debate coletivo

Aplique o que você construiu hoje

Pense sozinho por 1 minuto em cada cenário, depois debata com a turma. Os pontos-chave ficam escondidos para revisão.

Uma VM para cada sistema, no mesmo notebook. Tipo 2 (VirtualBox, VMware Workstation): roda sobre o Windows que você já usa. Atenção: o macOS só pode ser virtualizado legalmente em hardware Apple, pela licença da Apple.
Virtualização de servidores com hypervisor tipo 1 (ESXi, Hyper-V, KVM): sem SO hospedeiro no meio, com menos overhead e com recursos de data center, como migração ao vivo. Cada aplicação continua isolada na sua VM, e o hardware passa a ser bem aproveitado.
Snapshot logo antes da atualização: se der errado, restaura em segundos. Não substitui backup: fica no mesmo armazenamento e depende do disco original. Depois de validar a atualização, apague o snapshot; mantido por muito tempo, ele cresce e deixa a VM mais lenta.
Menos provável. O hypervisor apresenta à VM dispositivos emulados e padronizados (como placas Intel PRO/1000 no VirtualBox), com drivers que quase todo sistema já traz. No físico, o hardware varia por fabricante e modelo.
Uma VM-modelo com um snapshot base: no início de cada aula, todos restauram o snapshot. Para muitas máquinas, distribua um .ova ou crie clones vinculados a partir do mesmo snapshot.

30 · Glossário da aula

Termos que você precisa dominar

Virtualização
Camada de software que permite que vários sistemas compartilhem o mesmo hardware, isolados.
Máquina virtual (VM)
Computador completo simulado em software, com CPU, memória, disco e rede virtuais.
Hypervisor
Software que cria, executa e gerencia VMs.
Tipo 1 / tipo 2
Hypervisor direto no hardware (bare-metal) / hypervisor como programa sobre um SO host.
Host / guest
Sistema da máquina real (hospedeiro) / sistema dentro da VM (convidado).
Contêiner
Isolamento de processos que compartilham o kernel do host. Mais leve que uma VM.
VT-x / AMD-V
Instruções do processador que aceleram a virtualização. Ativadas no UEFI/BIOS.
vCPU / overcommit
Núcleo virtual / alocar mais recursos virtuais do que existem fisicamente.
Disco dinâmico / fixo
Arquivo que cresce conforme o uso / arquivo que reserva todo o espaço na criação.
ISO
Arquivo-imagem de um disco de instalação.
Hash (SHA-256)
"Impressão digital" de um arquivo: muda completamente se um bit mudar.
MBR / GPT
Tabelas de partição: a antiga (até 2 TiB, 4 primárias) e a atual (usada com UEFI).
Guest Additions
Drivers do VirtualBox instalados no convidado: tela, área de transferência e pastas.
NAT / bridge
VM sai pelo IP do host / VM ganha IP próprio na rede física.
Snapshot
Estado salvo da VM para onde se pode voltar. Não é backup.
Clone vinculado
Cópia que reaproveita o disco original e grava só as diferenças.
OVA
Arquivo único com VM e discos, para exportar, importar e fazer backup.
Migração ao vivo
Mover uma VM ligada entre hosts físicos, sem parar o serviço.
